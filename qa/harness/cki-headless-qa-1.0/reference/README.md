# reference/ —— 基线

这一目录里的东西是**证据**，不是素材。改动它们等于改基线，请连同哈希一起改。

## 基线锚定在哪份 ROM 上

```
input  (注入前) sha256 = 280eeb2f24dbdf1413a8e7977b46fc7684f4c26499669dbbe24e9106eccb562c
output (注入后) sha256 = 9bb898a446518f8d5964c87587b41ecde577a55dc41e4121db9f53532fe16ec5
```

上面那份 output 就是 `pokeemerald-ch` 的 CKI 1.0 注入产物、GNU 工具链（arm-none-eabi-gcc 13.2.1）
那条路走出来的 ROM。基线**只对它有效**。换一份 ROM 就必须重录。

三处 ROM 相关常量（读自注入报告）：

| 名称 | 值 | 含义 |
| --- | --- | --- |
| `CK_NS_PTR` | `0x02036240` | 命名屏指针（`resolver.naming_screen_global`）存在这个地址里 |
| `CK_NAME_BUF` | `0x1800` | 名字缓冲区在 NamingScreen 结构内的偏移 |
| `CK_LOCK_STATE` | `0x1e26` | 适配器的 `0xF000 \| page` 锁字 |

## 这些参考帧是怎么来的

2026-09-25 在本机 WSL(Ubuntu 24.04) 上，用本包的 `src/qa_boundary_v10.c`
编译后跑上述 output ROM 生成，随后：

1. 行为日志与仓库里既有的基线逐字节相同；
2. 同一 ROM 连跑两遍，7 帧原始字节全部相同（`verify.sh` 第 3 项）；
3. 与上游交付包那批截图对拍，差异 1.19%–1.59%，且差异全部落在键盘网格区域 ——
   正是后来修掉的两处缺陷（过时的 `lower` 字条、未对齐的选框）。
   如果本包的字节序搞错了，差异会接近 100%，不会只有 1.3%。

也就是说：**这批参考帧本身经过了一次独立对拍**，不是"自己生成、自己签收"。
