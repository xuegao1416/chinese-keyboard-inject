known_defective/ —— 反面教材，不是基线
========================================

这里这 7 张图 + 1 张拼图，来自上游交付包，交付时被标注为
"visual gate passed"（视觉门禁通过）。

那句话是错的。

放到本机的无头截图台上、对同一份 ROM 重跑、逐像素对拍，结果是：

    帧              不同像素      占屏比      差异范围
    locked_empty    482/38400     1.255%      x 32..214  y 31..95
    1cn             512/38400     1.333%      x 32..214  y 31..95
    2cn             523/38400     1.362%      x 32..214  y 31..95
    3cn             571/38400     1.487%      x 32..214  y 31..95
    4th             585/38400     1.523%      x 32..214  y 31..95
    delete          457/38400     1.190%      x 49..214  y 31..87
    readd           612/38400     1.594%      x 32..214  y 31..95

差异全部落在 4 行 x 16 像素的键盘网格区域。放大看，这批旧帧里：

  1. 右列还是原版的 "lower" 字条 —— 后来才被改写成「切换」；
  2. 网格上没有对齐到字形的高亮选框 —— 后来才修好。

对比 reference/behaviour_montage.png（通过门禁的样子）一眼就能看出来。

为什么要留着
------------
因为它证明了两件事：

  * "视觉通过"这句话，如果没有"能重跑出这批帧的 ROM 哈希 + 输入脚本"，
    等于没说；
  * 目检是必须的。这批图被签了通过，缺陷却明明白白印在像素上，
    只是没人真去看。

不要拿它当基线
--------------
里面的是 reference_montage.png 和 v10_*.png。
`verify.sh` / `png_cmp.py` 对比的是上一层 reference/，不是这里。
本目录仅供"知道自己该看什么"之用。
