# 按键脚本语法

`scripts/*.txt` 是 `gba_capture` 的输入。一行一条命令，`#` 之后是注释，空行忽略。
地址一律写十六进制（`0x` 开头）。

## 命令

| 命令 | 作用 |
| --- | --- |
| `frames N` | 空跑 N 帧 |
| `key NAME [按下帧数] [松开帧数]` | 按一下某个键。默认 **2 帧按下、120 帧松开** |
| `hold NAME` / `release NAME` | 把键按住 / 松开（不推进帧） |
| `repeat N <命令>` | 把后面那条命令重复 N 次 |
| `ptr SYM 0x地址` | 定义符号 `SYM` = 该地址里存的 32 位指针（每次用到时**实时读取**） |
| `untillive SYM 低 高 最多几次 [键]` | 循环按键（默认 A），每按一次检查 `SYM` 是否落在 `[低,高)` 内，落进去就提前停 |
| `shot 名字` | 把当前帧写成 `输出目录/名字.raw`（256×256×4 字节） |
| `text "字符串"` | 往日志里写字符串，支持 `\n`、`\t`，不自动换行 |
| `peek 地址 字节数 [be]` | 从地址读 N 字节，按十六进制写进日志，不换行；`be` 表示倒序输出 |
| `peek32 地址 [be]` | 读一个 32 位字，输出 8 位十六进制 |

`NAME` 取值为 `A B SELECT START RIGHT LEFT UP DOWN R L`（大小写不敏感）。

## 地址写法

- `0x02036240` —— 直接写绝对地址
- `NS` —— 符号 `NS` 所指的指针（实时读取）
- `NS+0x1800` —— 上面那个指针再加偏移

## 按键时序：不要动

`key` / `untillive` 默认 **按下 2 帧、松开 120 帧**。这个数字是 CKI 1.0 行为基线录制时用的，
**必须逐字照抄**。

改成 60 帧"看着差不多"，实际会让"连打 A 直到进入某界面"的循环落在完全不同的位置，
之后读到的内存全是垃圾 —— 典型表现是锁状态读出一串毫无意义的值，而你会以为是 ROM 的问题。

要改时序可以，但改完必须**重录基线**，并明白旧基线不再适用。

## 上下文

一条 `key` 会推进 122 帧，一条 `frames 600` 就是 600 帧。整条 `chinese_gate.txt`
大约 7400 帧，headless 下几秒跑完。

## 例：`chinese_gate.txt` 摘录

```
ptr NS 0x02036240          # 命名屏 EWRAM 指针的存放地址
frames 600                 # 开机
untillive NS 0x02000000 0x02040000 40 A   # 连打 A，直到指针落到 EWRAM
frames 180
repeat 8 key RIGHT         # 光标移到换页标签
key A                      # 进中文模式

text "locked_empty "       # 日志前缀
peek NS+0x1800 10          # 名字缓冲区 10 字节
text " state="
peek NS+0x1e26 2 be        # 锁状态字，倒序
text "\n"
shot v10_locked_empty      # 存帧
```

## 加新步骤的建议

1. 先 `shot` 存一帧，转成 PNG 看一眼，确认自己真的在那个界面上；
2. 再用 `peek` 读内存。**先看图再读内存**，顺序反了很容易对着垃圾数据编故事；
3. 每次新增步骤后，整条脚本重跑一遍，确认新步骤没有把后面的步骤挤偏。

## CKI 的四条脚本

两条**模板**带两个哨兵字面量，由 `tools/qa_bench/qa_one.sh` 按宿主替换后才跑：

- `cki_probe_template.txt` —— 门禁 4（行为）+ 5（视觉）的 10 步探针：冷启动走到命名界面、
  翻到 PAGE 格、`A` 进中文模式、连按上屏、`B` 整字删除、`SELECT` 解锁、再锁回去。
  NS 哨兵 `0x02035358` 出现 3 次（注释、`ptr` 绑定、绝对 `peek`）。
- `cki_boundary_template.txt` —— 门禁 4 的完整 27 步边界路线，除 NS 哨兵外还要光标哨兵
  `0x00FF00FF`（= 该宿主 `sprites_global+0x2E`）。每一步的期望值都从
  `payload/adapter_v10.c` 推导，而不是从截图反推。

两条**已替换的实例**（基线宿主 `pokeemerald-ch_modern_build`，NS = `0x2036240`）：
`cki_probe.txt`、`cki_boundary.txt`。留着它们是为了让"替换之后长什么样"有据可查——
真跑的时候不要手改这两份，走模板。
