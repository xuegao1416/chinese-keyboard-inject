# 坑（都踩过，都留了判据）

分两部分：**A** 是这套工具自身的坑 —— 动 `src/` 或改脚本之前先看；
**B** 是"用这套工具去验 ROM 补丁"时会遇到的坑 —— 改 ROM 图形/载荷的人看。

每条都写了**判据**：怎么用一句话判断自己是不是掉进去了。

---

# A. 工具本身的坑

## A1. 绝对不要加 `-DCOLOR_16_BIT`

发行版的 `libmgba` 是按 **32 位 `color_t`** 编出来的（`sizeof(color_t) == 4`）。
如果本地加了 `-DCOLOR_16_BIT`，你的 `color_t` 变成 `uint16_t`：

- 你声明 128 KB 的帧缓冲，
- 库往里面写 256 KB。

**编译零警告，跑第一帧就段错误**，而且堆栈里看不出跟色深有任何关系。

- 判据：不加那个宏就正常。
- 防呆：两个 `.c` 里都有
  `_Static_assert(sizeof(color_t) == 4, ...)`，
  `build.sh` 还会在 `CFLAGS` 里搜到 `COLOR_16_BIT` 时直接拒绝编译。
  `check_env.sh` 第 6 项也会实测打印 `sizeof(color_t)`。

## A2. 按键时序必须逐字照抄（2 帧按下 / 120 帧松开）

`gba_capture` 和 `qa_boundary_v10` 用的都是"按下 2 帧、松开 120 帧"。
这是 CKI 1.0 行为基线录制时的时序。

"改成 60 帧看着差不多"是错的：`untillive` / "连打 A 直到进入某界面"这类循环
会因此落在**完全不同的位置**，之后读到的内存全是垃圾。
典型表现是锁状态读出一串毫无意义的值（例如 `0x1111`），而你会以为是 ROM 坏了。

- 判据：行为日志与 `reference/qa_boundary_v10_result.log` 对不上，但画面看着正常。
- 要改时序可以，改完**必须重录基线**，并且明白旧基线作废。

## A3. 帧缓冲是 32 位、`0x00BBGGRR`，**红在最低字节**

`.raw` 是 `fwrite(fb, sizeof(color_t), 65536, f)`，即 65536 个像素、
每像素 4 字节、小端 `uint32`：

```
R = v & 0xFF      G = (v >> 8) & 0xFF      B = (v >> 16) & 0xFF
```

GBA 可见画面是这 256×256 缓冲的**左上角 240×160**。

- 判据：用 `python3 tools/raw2png.py --probe 120,80 文件.raw` 打印某个已知颜色的像素。
  草地变棕色、天空变橙色 → 通道顺序搞错了。
- 注意：如果写成 16 位，`.raw` 会是 131072 字节。`raw2png.py` / `montage.py`
  会**拒绝**这种文件并让你回去重编，不会硬转出一张错图。

## A4. mGBA 自己的日志关不掉（`logLevel` 配置项无效）

mGBA 默认每个 DMA、每个 SWI 打一行，一次运行 **2958 行**，把你要的那条日志埋了。

**实测**：设 `mCoreConfigSetOverrideIntValue(&config, "logLevel", 8)`
**没有任何效果**，还是 2958 行。配置项根本不接这个开关。

正确做法是换掉默认 logger：

```c
static void quiet_log(struct mLogger* l, int cat, enum mLogLevel lvl,
                      const char* fmt, va_list args) { /* 丢掉 */ }
static struct mLogger QUIET_LOGGER = { .log = quiet_log, .filter = NULL };
...
mLogSetDefaultLogger(&QUIET_LOGGER);      /* 见 src/gba_capture.c */
```

- 实测结果：默认 0 行输出，`--verbose` 2958 行。
- **别把这段当装饰删掉**：排查问题时要 `--verbose`，
  `Invalid video register`、`Bad BIOS Load8` 这类是真信号。

## A5. 原地分词器不能复用同一个缓冲区

`run_line()` 是**原地**把行切成 token（往行里写 `\0`）。
所以 `repeat` 不能把同一块缓冲区喂两遍 —— 第二遍只会看到第一个 token。

这个坑真的踩到了：`repeat 8 key RIGHT` 第一次成功、第二次报
`key needs a button name`，因为第二次读到的字符串已经只剩 `key`。

修法是每轮拷一份：

```c
for (int i = 0; i < k; i++) {
    char one[2048];
    memcpy(one, buf, w + 1);
    run_line(one, lineno);
}
```

- 判据：`repeat N cmd` 里 N > 1 时报"参数不够"，而单独写那条命令是对的。

## A6. 别人给的"视觉通过"截图，不能当证据

本包里 `reference/known_defective/` 就是一份实物：
那是上游交付包声称"visual gate passed"的 8 张截图。

用本工具在同一台机器、同一份 ROM 上重跑，逐像素对拍的结果：

| 帧 | 不同像素 | 占屏比 |
| --- | --- | --- |
| locked_empty | 482 / 38400 | 1.26% |
| 1cn | 512 / 38400 | 1.33% |
| 2cn | 523 / 38400 | 1.36% |
| 3cn | 571 / 38400 | 1.49% |
| 4th | 585 / 38400 | 1.52% |
| delete | 457 / 38400 | 1.19% |
| readd | 612 / 38400 | 1.59% |

差异全部落在 `x 32..214, y 31..95` —— 正好是 4 行 ×16 px 的键盘网格。
放大看，旧帧里：

- 右列还是原版的 `lower` 字条（后来被改写成「切换」）；
- 网格上没有对齐到字形的高亮选框。

也就是说，那批截图**本身带着后来才修掉的缺陷**，只是没人真去看像素。

- 判据：任何"视觉通过"的结论，必须附上**能重跑出这批帧的 ROM 哈希 + 输入脚本**。
  没有这两样，"通过"两个字没有意义。
- 顺带说明本包的 `tools/raw2png.py` 字节序是对的：如果通道顺序错了，
  差异会是接近 100% 而不只是 1.3%。

# B. 用这套工具验 ROM 补丁时的坑

改 ROM 图形/载荷的人会踩到这些。都是项目里实测出来的。

## B1. GBA 的 VRAM 不能用 8 位访问

往 VRAM / 调色板 RAM 写图形时：

- **8 位写（`*(u8*)0x06010000 = x`）会被硬件丢弃**，8 位读返回重复数据；
- VRAM 只接受 **16 位或 32 位**访问（引擎自己用的 `CpuCopy16` 那种）。

改成 `volatile u16*` 之后，同一段逻辑从"什么都不发生"变成"正常工作"。

- 判据：状态机报告成功，但把字节读回来发现等于原值 —— 写根本没落地。

## B2. 改 4bpp 图块的**单个像素**时，掩码要按 4 位算

一个 16 位字里装 **4 个像素**（每字节 2 个，低半字节在左）。
按字节选掩码（`0x00FF` / `0xFF00`）并用 `x&1` 判断，会：

1. 每写一个像素**连带抹掉邻居**；
2. `(x&3)>=2` 时**写错字节**。

屏幕上的表现是**整个字形化成竖条**，编译器一句警告都不会给。

## B3. Thumb on ARMv4T 没有除法指令

`a/b`（**哪怕 b 是编译期常量**）都会变成对 `__aeabi_idiv` / `__aeabi_uidiv`
的外部引用，`-nostdlib` 链接直接失败：
`ld.lld: undefined symbol: __aeabi_uidiv`。

**自己写减法循环也没用**：编译器会把 `while (a >= b) { a -= b; q++; }`
识别成除法，换成同一个调用。

可行做法：定点倒数 + 移位（`q = (unsigned)(n * 3641u) >> 15` 在 n ≤ 128 时
精确等于 `n / 9`），配 `#if 常量 != 9 #error` 防呆；除 2 直接 `>> 1`。
最省事的是结构上避免 —— 能 1:1 就 1:1，不够就裁，别缩放。

## B4. "补丁位点存在" ≠ "补丁位点被执行"

项目里踩过一次：某帧位点被挂在一段**死代码**（编译器生成的尾巴调用壳）上，
结果是 L/R 翻页和 SELECT 退出在每个产物里都是死的，而所有静态检查都"通过"。

- 规矩：**任何新增补丁位点，都要有一条"它确实被执行了"的实机实测**。
  本工具就是干这个的：`shot` 看画面 + `peek` 看内存，两者都要有。
